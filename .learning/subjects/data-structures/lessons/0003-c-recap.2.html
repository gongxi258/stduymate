结构体：把字段打包带走

本节目标：能用结构体与 typedef 定义并访问一个数据记录

一条记录该放哪

通讯录里每条记录有三个字段：姓名、电话、分组。字段不多，先用最直白的办法存——一个字段开一个数组：

char name[3][12]  = { "林小雨", "王工", "陈老师" };
char phone[3][12] = { "13800001111", "13900002222", "13700003333" };
char group[3][8]  = { "同学", "同事", "老师" };

第 0 条记录的三个字段分别是 name[0]、phone[0]、group[0]。同一个人的三个数据项分散在三个数组里，靠下标凑在一起。

只在原地读一读还算顺手，一旦要动它，麻烦就出现了：

  • 删一个人要动三处：把「王工」从通讯录里去掉，得在三个数组里各删一次第 1 个元素，漏掉一处就留下半条记录；
  • 传出去要传三样：写一个「打印一条通讯录记录」的函数，就得给它三个参数；哪天记录再加一个「备注」字段，这个函数以及每一处调用都要跟着改；
  • 一条记录不是一个东西：三个数组各自是一整份东西，没人替它们记住「第 1 个位置上的三段合起来才是王工」。

第一课讲过，一个完整的数据结构除了存数据，还要有定义在它上面的运算；运算写得顺不顺，就看数据是怎么存的。三个字段本来属于同一条记录，却被摊成了三份互不相干的存储，运算自然要四处迁就。

C 给这件事提供的办法，是把几个字段装进一个单位里，让「一条记录」在程序里真的成为一个东西：

struct Contact {
    char name[12];
    char phone[12];
    char group[8];
};

这一节之后，上面那三个数组就会被 struct Contact 取代，一次函数调用就能把整条记录传出去。

写下这条声明时只讲了「一种叫 struct Contact 的类型由哪几个字段组成」，还没有划出任何内存。

先有类型，再有变量

上面那段 struct Contact { … }; 是一条声明。要读懂它，先分清花括号里外两件事。

struct Contact 是整个类型的名字：关键字 struct 加上一个名字（这个 Contact 叫标签）。花括号里列的是一串成员，每个成员的写法与声明普通变量一样——先写类型，再写名字，末尾一个分号。分号不能省，漏掉最后一个分号时，编译器给出的报错往往指到下一行，找起来容易白费功夫。

这条声明只讲清了一种新类型长什么样，还没有划出任何内存。 这与第一课讲的类型与变量是同一回事：int 是一种类型，int x; 才是一个变量；struct Contact 是一种类型，下面这一行才是变量：

struct Contact c;          /* 一个结构体变量，三个字段都在里面 */

声明变量时就能直接把字段填好，按成员的书写顺序给：

struct Contact c = { "林小雨", "13800001111", "同学" };

要访问某个字段，写变量名、一个点、成员名：

#include <stdio.h>

struct Contact {
    char name[4];
    char phone[12];
    char group[8];
};

int main(void) {
    struct Contact c = { "Lin", "13800001111", "friend" };

    printf("姓名：%s\n", c.name);
    printf("电话：%s\n", c.phone);
    printf("分组：%s\n", c.group);

    c.group[0] = 'X';               /* 改的是 c 里 group 这一段 */
    printf("改过之后：%s\n", c.group);
    return 0;
}
姓名：Lin
电话：13800001111
分组：friend
改过之后：Xriend

三点值得记住：

  • 点运算符（.）取的是「这个变量里的哪个成员」，c.name 这种写法在表达式里与一个同类型的普通变量用起来一样，可以读、可以写、可以再取下标；
  • 命名互不干扰：结构体里的 name 与外面另有一个叫 name 的变量互不影响，c.name 里的那个 name 只在 c 这个类型里有意义；
  • 成员的量法与上一课一样：c.name 是 char 数组，sizeof(c.name) 就是它占的字节数；c.group[0] 是数组里的一格，用 %c 打印字符、用 %d 打印会得到一个数（负数在这里是正常的）。一个汉字要占两个字节以上，所以「改一格」这类操作只适合英文那类一字一字节的内容——本课练习的第 1 步有一小问可以自己试。

最后把「传出去要传三样」这件事解决掉。上一课的参数框架在这里第一次显出好处：

#include <stdio.h>

typedef struct Contact {
    char name[12];
    char phone[12];
    char group[8];
} Contact;

void print_contact(Contact c) {
    printf("整条记录：%s  %s  %s\n", c.name, c.phone, c.group);
}

int main(void) {
    Contact c = { "林小雨", "13800001111", "同学" };
    print_contact(c);
    return 0;
}
整条记录：林小雨  13800001111  同学

函数的括号里可以直接写 Contact，调用处一次只传 c 这一个东西。这一行能写成这样，靠的正是上一节把三个字段并进了一个单位。

点与箭头

上一课留了一句：p->name 这样的写法下一课再讲。现在补上。

结构体变量用点取成员，那「指向结构体的指针」怎么取成员？先看它的地址：

struct Contact  c = { "林小雨", "13800001111", "同学" };
struct Contact *pc = &c;          /* pc 是指向 struct Contact 的指针 */

pc 里装的是 c 那一块的起点地址，与上一课的指针是同一套东西：声明时星号前面的类型写 struct Contact，指针就指向那种结构体。要取成员，有两种写法，说的是同一个成员：

printf("(*pc).phone = %s\n", (*pc).phone);
printf("pc->phone   = %s\n", pc->phone);
(*pc).phone = 13800001111
pc->phone   = 13800001111

第一种写法拆成两步读：*pc 先顺着地址找到那个结构体，再对找到的结构体用点取成员。这里的括号不能省：点运算符比 * 先结合，写 *pc.phone 会被理解成 *(pc.phone)，也就是拿 pc 去取成员，而 pc 是指针，编译器会报错。

第二种写法 pc->phone 就是第一种的简写，省掉那对括号，念作「顺着 pc 去取成员」。

一个符号，两种对象，配两种写法。这张表按「左边那个东西是什么」来分：

左边的写法它是取成员写例子
c结构体变量本身.c.phone
pc指向结构体的指针->（或 (*pc).）pc->phone

写反了都会报错：对指针用点、对结构体变量用箭头，编译器都不接受。读别人的代码时先看左边那一项是什么，写法就定下来了。

给类型起个短名字

struct Contact 每次都要写全，声明一个指针要写 struct Contact *pc，函数参数也要写 struct Contact。C 提供了一个给已有类型起新名字的工具：

typedef struct Contact Contact;

typedef 这一行的读法是「把 struct Contact 这个名字，另外叫做 Contact」。从此两种写法完全等价，Contact c; 与 struct Contact c; 声明的是同一种类型。

它的作用范围要说准：typedef 只是给一个已经存在的类型加了个名字，没有造出新类型。 上一节里 struct Contact 与 Contact 是同一种类型，能互相赋值、能互相传参，编译器看它们没有半点区别。标准库里的 size_t、time_t 就是这么来的名字，那些以 _t 结尾的名字由标准库占用，自己写代码时不要起这种名字。

给结构体起名字有一段惯用写法，把两行并成一行：

typedef struct Contact {
    char name[12];
    char phone[12];
    char group[8];
} Contact;

花括号后面那个 Contact 是新起的名字，前面那个 Contact 是标签。两者同名是允许的，代码里最常见；名字不同也可以（例如标签叫 struct contact_tag、新名叫 Contact），只是多了一个要想的名字。

类型有了短名字，后面几节的代码都只用 Contact。

字段在内存里怎么排

结构体是「几个字段装进一个单位」，这个单位在内存里是一块连续的内存：字段按声明的先后顺序依次排开，整块的起点就是这块内存的编号。

拿通讯录那条记录问一下尺寸：

#include <stdio.h>
#include <stddef.h>          /* offsetof 在这个头文件里 */

typedef struct Contact {
    char name[12];
    char phone[12];
    char group[8];
} Contact;

int main(void) {
    printf("sizeof(Contact) = %zu\n", sizeof(Contact));
    printf("name 从第 %zu 字节起\n", offsetof(Contact, name));
    printf("phone 从第 %zu 字节起\n", offsetof(Contact, phone));
    printf("group 从第 %zu 字节起\n", offsetof(Contact, group));
    return 0;
}
sizeof(Contact) = 32
name 从第 0 字节起
phone 从第 12 字节起
group 从第 24 字节起

sizeof 量这一块整占几个字节，量出来是 32，正好等于 12 + 12 + 8。offsetof 回答的是「某个成员从整块的起点算起，落在第几字节上」，这个量叫偏移（offset）。这两样都不用手算：字段一改、类型一换，把程序再跑一遍就有准数。

上面这个例子里三个成员都是 char 数组、宽度都是 1 的倍数，排得严丝合缝。换个成员类型就没这么整齐了：

#include <stdio.h>
#include <stddef.h>

typedef struct Record {
    char   tag;
    int    number;
    double score;
} Record;

int main(void) {
    Record r = { 'A', 7, 92.5 };

    printf("sizeof(Record) = %zu\n", sizeof(Record));
    printf("tag 从第 %zu 字节起\n", offsetof(Record, tag));
    printf("number 从第 %zu 字节起\n", offsetof(Record, number));
    printf("score 从第 %zu 字节起\n", offsetof(Record, score));
    printf("三个字段的宽度之和 = %zu\n",
           sizeof(char) + sizeof(int) + sizeof(double));
    printf("r.tag=%c r.number=%d r.score=%.1f\n", r.tag, r.number, r.score);
    return 0;
}
sizeof(Record) = 16
tag 从第 0 字节起
number 从第 4 字节起
score 从第 8 字节起
三个字段的宽度之和 = 13
r.tag=A r.number=7 r.score=92.5

一个 char、一个 int、一个 double 合起来是 13 字节，sizeof 给出来的却是 16。多出来的那 3 个字节在 tag 与 number 之间：tag 只占 1 字节，number 的起点落在第 4 字节上，中间这 3 个字节就空着。

这 3 个字节不算某个成员的存储，谁也没用到它。原因在上一课讲过的单位上：指针加减的单位是所指类型的宽度，int 一次读写 4 个字节、double 一次读写 8 个字节。硬件按这种宽度一次取一块内存，取的时候要求这一段从一个能被宽度整除的位置开始——int 从 4 的倍数地址开始、double 从 8 的倍数地址开始。这种「起始位置必须落在宽度的整数倍上」的要求叫对齐（alignment），编译器在成员之间空出来的那几个字节叫对齐填充（padding）。

于是布局规则有两条：

  1. 每个成员从自己对齐要求允许的位置开始，前面不够就垫几个填充字节；
  2. 整块的长度补到最大的那个对齐要求的整数倍——这样连续放 Record 数组时，每个元素都还满足对齐要求。

这两条都是编译器按平台定的，C 标准只要求成员能对齐、并规定成员按声明顺序依次排开（N2310 §6.7.2.1 第 14–17 段），填充几个字节、填在哪里由实现决定。所以 sizeof(struct S) 不能拿字段宽度相加去估，用 sizeof 与 offsetof 量出来才准。把字段换个顺序有时能省下几个字节，涉及大量记录时才值得计较。

结构体赋值是整份复制

结构体让「一条记录」成了一个单位，赋值这件事也跟着变简单了：结构体变量可以用 = 整体赋值。

#include <stdio.h>

typedef struct Contact {
    char name[12];
    char phone[12];
    char group[8];
} Contact;

int main(void) {
    Contact a = { "Tom", "13800001111", "同学" };
    Contact b = a;                 /* 把 a 那一块整个复制给 b */

    printf("复制之后：b.name = %s\n", b.name);

    b.name[0] = 'J';               /* 只改 b */
    printf("改过 b 之后：a.name = %s，b.name = %s\n", a.name, b.name);
    printf("a.phone = %s，b.phone = %s\n", a.phone, b.phone);
    printf("&a = %p\n", (void *)&a);
    printf("&b = %p\n", (void *)&b);
    return 0;
}
复制之后：b.name = Tom
改过 b 之后：a.name = Tom，b.name = Jom
a.phone = 13800001111，b.phone = 13800001111
&a = 000000468F3FF7B0
&b = 000000468F3FF790

两点从输出里读出来：

  • 改 b.name 之后 a.name 还是 Tom。b = a 做的事是把 a 那一块的字节逐个复制到 b 那一块里去——这一整块连同对齐填充一起复制。复制完两个变量各占一块内存，&a 与 &b 是两个不同的编号（这两个数每次运行都会变，看的是它们不相等这一件事），从此互不相干：改 b 里的任何字段都碰不到 a。
  • 两个变量各自占一块 32 字节。在上一课，一个 int 变量的副本是 4 个字节；这里一个结构体变量的副本是整块 32 字节，道理一样，只是拷贝的东西变大了。

C 对结构体另有一条限制值得记住：结构体可以用 = 赋值，不能用 == 或 != 比较。 想判断两条记录是不是同一个人，得自己挑字段比，例如 strcmp(a.phone, b.phone) == 0。原因不在本课范围内，先记住这条规矩。

成员里若装的是地址，复制过去的也是那个地址：

typedef struct Node {
    int          value;
    struct Node *next;
} Node;

Node x = y; 会把 y.next 里那个地址原样复制给 x.next——两份结构体里的成员指向同一个地方，不会替你把那个地方再复制一份。这一点到链表那一课会天天用到。

结构体作参数

上一课留下了一套问两次的框架，用来读任何一次函数调用：① 函数拿到的是原件还是副本？② 副本里装的是什么？ 现在把结构体放进这套框架里，两问都还在。

第一问的答案没有变：函数拿到的是副本。 结构体作参数时，副本是整整一块——main 里那个变量占 32 字节，函数里的参数就另占 32 字节，调用时把整块复制过去。C 标准在讲参数传递时写的是「每个参数被赋予对应实参的值」，结构体变量的「值」就是整块内容，所以整块都被赋了过去。

#include <stdio.h>
#include <string.h>

typedef struct Contact {
    char name[12];
    char phone[12];
    char group[8];
} Contact;

void set_group_copy(Contact c, const char *g) {
    strcpy(c.group, g);            /* 改的是函数里这一份 */
    printf("函数里：c.group = %s，&c = %p\n", c.group, (void *)&c);
}

void set_group(Contact *pc, const char *g) {
    strcpy(pc->group, g);          /* 顺着地址写回调用方那一块 */
    printf("函数里：pc = %p\n", (void *)pc);
}

int main(void) {
    Contact c = { "林小雨", "13800001111", "同学" };
    printf("main 里：&c = %p，c.group = %s\n", (void *)&c, c.group);

    set_group_copy(c, "同事");
    printf("按值传之后：c.group = %s\n", c.group);

    set_group(&c, "同事");
    printf("传地址之后：c.group = %s\n", c.group);
    return 0;
}
main 里：&c = 00000090889FFB00，c.group = 同学
函数里：c.group = 同事，&c = 00000090889FFAE0
按值传之后：c.group = 同学
函数里：pc = 00000090889FFB00
传地址之后：c.group = 同事

函数里那个 c.group 确实变成了「同事」，可第二行给出的地址与第一行不一样（这两个数每次运行都会变，看的是它们不相等这一件事）：main 那一份在 …FB00，函数里那一份在 …FAE0。两块内存，两份数据；函数改的是自己那 32 字节，main 这一份没人碰，所以第三行打印出来还是「同学」。上一课 swap_wrong 的 a、b 是这样，这里的 c 还是这样——差别只在于副本变大了：从一个 int 的 4 个字节，变成了一整块 32 字节。

第二版才是那个能把记录改成的版本。参数写成 Contact *pc，收到的是一个装着地址的副本，里面是 main 那个 c 的起点；这一次 pc 打印出来的编号与 main 的 &c 完全一样（都是 …FB00）。函数里用 pc->group 顺着地址摸回调用方那一块，改的就是原件了：最后一行打印的分组变成了「同事」。传下去的还是副本，只是副本里装的是地址。

卡住时先翻这两页

上一课的格子模型、&x 与 *p、两问框架、两个 swap 的逐行走查，都收在指针与传参速查。本节这两段代码与 swap_right 的走法完全一样，只是把 int 换成了 Contact；卡住就先翻它，再回来看正文。

链表结点的最后一块拼图

现在可以把结构体接到本科目的主线上。项目「C 小容器库」要做的第一个链式结构是单链表，它的结点需要两样东西：一份数据，和一个指向下一个结点的地址。这两样正好是结构体的两个成员：

typedef struct Node {
    int          value;          /* 数据 */
    struct Node *next;           /* 下一个结点在哪 */
} Node;

第二行的写法里有一处新东西：成员的声明用了 struct Node *，而这个标签 Node 正是当前这条声明本身。C 标准规定结构体不能直接装一个自己的实例（那样长度没法算完），但可以装一个指向自己的指针（N2310 §6.7.2.1 第 3 段）。指针的长度是固定的 8 字节，装得下。

#include <stdio.h>

typedef struct Node {
    int          value;
    struct Node *next;
} Node;

int main(void) {
    Node  n2 = { 2, NULL };            /* 尾结点的 next 是空指针 */
    Node  n1 = { 1, &n2 };             /* n1 的 next 装着 n2 的地址 */
    Node *p  = &n1;

    printf("n1.value = %d，n1.next->value = %d\n", n1.value, n1.next->value);
    printf("p->value = %d，p->next->value = %d\n", p->value, p->next->value);
    printf("sizeof(Node) = %zu\n", sizeof(Node));
    return 0;
}
n1.value = 1，n1.next->value = 2
p->value = 1，p->next->value = 2
sizeof(Node) = 16

n1.next->value 从里往外读：先取 n1 的 next 成员，它是一个指向 Node 的指针；再顺着它取 value。p->next->value 一样是多走一步。读这种连起来的箭头，从左往右一步一步落到具体的格子上就不会乱。

sizeof(Node) 是 16：int 占 4 字节，指针占 8 字节，前一个成员后面垫了 4 字节填充——正是上一节讲的两条规则在这里的应用。

单链表的每一个结点都是这个 Node：函数收到的每一个结点、头指针指向的每一个结点，都是这样一块 16 字节的内存。有了它，下一课就能把结点一个个申请出来、用 next 串成一条链。

把类型放进头文件

到了一个源文件放不下的时候，这个类型要被好几处用到：链表容器有 list.h 与 list.c 两个文件，结点类型两边都要看得见；测试文件也要用到它。

C 的做法是把类型声明放进头文件（.h），要用它的源文件写一行 #include。比如 list.h 里放结点与链表的类型，list.c 与测试文件各自 #include "list.h"。一条类型声明只写一份，改一处就够了——这也是 print_contact 那个「多一个字段要改几处」的问题在文件层面的答案。

头文件有个必须防的坑：同一个源文件可能把它包含两次。例如 list.c 自己包含 list.h，它包含的另一个头文件里也包含了 list.h；而 struct Node 这种声明在同一个文件里出现两次就会报重复定义。办法是给头文件加一对包含卫兵：

#ifndef LIST_H
#define LIST_H

typedef struct Node {
    int          value;
    struct Node *next;
} Node;

#endif

读法是：第一行问「LIST_H 这个名字还没被定义过吗」。第一次处理这个文件时它确实没定义，于是往下走、第二行把它定义掉；文件被第二次包含时，第一行发现名字已经有了，就一路跳到末尾的 #endif，整段不再重复。一句话说明它在挡什么：挡的是同一个头文件被重复读进同一个源文件。名字按文件名取、全大写（这里是 LIST_H），是这一行的惯例。

上一节那个结点类型就照这个办法放进 list.h：一块一块申请出来，再用 next 串成一条链。

本课只写几行

本课的代码都在十几行以内，一节一段，敲一遍、改一行、看输出。结构体的写法在后面的每一课里都会出现：链表的结点、二叉树的结点、哈希表的桶，都是先定义一种结构体，再定一组运算。

练习：改一行，看谁变

把下面这段存成 contact.c，编译时把警告开关带上：

gcc -std=c17 -Wall -Wextra -o contact contact.c
./contact

下面三步都用这条命令。每一步都在上一步的基础上改，改完再跑一次，对着输出说话。

练习 第 1 步 · 打印一条记录 
#include <stdio.h>

typedef struct Contact {
    char name[12];
    char phone[12];
    char group[8];
} Contact;

int main(void) {
    Contact c = { "林小雨", "13800001111", "同学" };

    printf("sizeof(Contact) = %zu\n", sizeof(Contact));
    printf("%s  %s  %s\n", c.name, c.phone, c.group);
    return 0;
}
  1. 输出里 sizeof(Contact) 是几？它与你把三个成员的宽度加起来算的数一样吗？
  2. 把 c.group[0] 改成另外的字符再打印 c.group，输出变了几个字符？
  3. 在 main 里加一句 Contact d = c;，再把 d.name 换一个值，两次打印 c.name 与 d.name——哪一份变了？
练习 第 2 步 · 传进去改一个字段

在上面那个文件里加两个函数，一个按值收、一个按地址收：

#include <string.h>

void set_group_copy(Contact c, const char *g) {
    strcpy(c.group, g);
    printf("函数里：c.group = %s，&c = %p\n", c.group, (void *)&c);
}

void set_group(Contact *pc, const char *g) {
    strcpy(pc->group, g);
    printf("函数里：pc = %p\n", (void *)pc);
}

在 main 里先打印 (void *)&c 与 c.group，再分别调用这两个函数，每次调用后都打印一次 c.group。

  1. 按值那一版：函数里打印的 &c 与 main 里打印的 &c，是同一个编号吗？调用之后 main 里 c.group 变了没有？
  2. 按地址那一版：函数里打印的 pc 与 main 里哪个编号相同？调用之后 c.group 变了吗？
  3. 两版都把 group 改成了「同事」，为什么一版看得出来、一版看不出来？
练习 第 3 步 · 一个结点，两个成员

把类型换成链表的结点，串两个结点起来：

typedef struct Node {
    int          value;
    struct Node *next;
} Node;

在 main 里声明 Node n2 = { 2, NULL }; 与 Node n1 = { 1, &n2 };，再声明 Node *p = &n1;。

  1. 用 p->next->value 打印第二个结点里的数，它是几？
  2. 把 p->next 与 &n2 都打印出来：两个编号一样吗？
  3. sizeof(Node) 是几？与「int 4 字节加指针 8 字节」相比多出来的那几个字节是什么？

自测

小结

  • 结构体把几个字段装进一个单位：struct 标签 { 成员声明; … }; 声明出一种新类型，struct Contact c; 才划出内存；typedef 只是给这个类型另起一个短名字。
  • 取成员两种写法：结构体变量用点（c.name），指向结构体的指针用箭头（pc->name，等价于 (*pc).name）；左边是什么，写法就定了。
  • 字段按声明顺序排在一块连续内存里，每个成员从对齐允许的位置起，中间和末尾可能有对齐填充；所以 sizeof 未必等于字段宽度之和，用 sizeof 与 offsetof 量。
  • 赋值是整份复制：b = a 之后两个变量各占一块内存，互不相干；结构体可以用 = 赋值，不能用 == 比较。
  • 结构体作参数也是整份副本：函数改的是自己那一块，调用方看不见；要改原件就传它的地址，函数里用箭头写回去。副本大小从上一课的 4 个字节变成了整块。
  • 链表的结点就是结构体：一个数据成员加一个指向下一个同种结点的指针成员——有了这一课，结点这块拼图就齐了。
  • ISO/IEC 9899（C17）标准草案 N2310：6.7.2.1 结构与联合说明符官方草案 · 本机已落盘；第 6 段是结构体的定义（成员按顺序分配存储）、第 8 段是「带成员列表的声明声明了一个新类型」、第 3 段是「结构体不能装自己的实例，但可以装指向自己的指针」、第 14–17 段是对齐与填充（成员按声明顺序地址递增、开头没有填充、末尾可以有填充）
  • ISO/IEC 9899（C17）标准草案 N2310：6.5.2.3 结构与联合成员官方草案 · 本机已落盘；第 1–2 段是 . 与 -> 各自要求左边是什么类型，脚注 100 写明 (&E)->MOS 与 E.MOS 是同一件事
  • Modern C（Jens Gustedt，第 2 版）第 6 章 · 派生数据类型书 · 本机已落盘；§6.3 是结构体（成员、初始化、嵌套），§6.4 是 typedef（「只给已有类型加名字，不造新类型」）
  • Modern C（Jens Gustedt，第 2 版）第 12 章 · C 的内存模型书 · 本机已落盘；§12.7 讲对齐：对象通常从字边界开始，强行放到不对齐的位置会出错
  • K&R《The C Programming Language》（第 2 版）第 6 章 Structures书 · 结构体与链表的经典入门一章；本机无正文，作为书目备查
