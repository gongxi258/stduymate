指针与传参速查

格子模型：名字、地址、内容

程序运行时的数据都放在内存里。内存按字节编号，每个字节有一个编号，这个编号称为地址。一个变量就是给一块数据起的名字：编译器在编程序时给它划出若干字节，这个名字从此与那段地址绑在一起。于是同一个变量同时有三个可以观察的量。

量怎么写出来以 int x = 20; 为例说明
名字xx写代码时用它。名字只活在程序里，运行时内存里没有名字，函数也只知道自己的参数名
地址&x0x7ffd38那一格的起始编号。同一段程序每次运行，整块栈的起始位置都可能不同，所以某一次的具体数字看过就算
内容x20格里实际装的东西：可以读出来，也可以改掉

指针是变量里特殊的一类：它的内容是一个地址。看它那一格时要分清两样东西——&p 是这一格自己的编号，p 是这一格里装的编号，两者都是编号，说的却是两块不同的格子。

取地址与解引用

& 是取地址运算符，&x 读作「x 的地址」，结果是 x 所在格子的编号。* 写在表达式里是解引用，*p 读作「按 p 里的地址去访问那一格」。

写法读作结果典型用途
xx 的内容那一格里装的东西读值、改值
&xx 的地址指向 x 的指针值存进指针变量；作为实参传给函数
pp 的内容它当前指着的那一格的编号换目标：p = &y
*p按 p 里的地址访问p 指着的那一格写在赋值号左边＝改那一格；写在右边＝读那一格
&pp 自己的地址p 这一格的编号与 &x 是两个不同的编号

改目标：p = &y;

改的是 p 自己这一格的内容，x、y 都不动。此后同一句 *p 落到 y 那一格。

改内容：*p = 35;

p 没有被赋值，改的是它当前指着的那一格：指着 x 就改 x，改成指着 y 就改 y。

解引用落到哪一格，由 p 的内容决定，与 p 自己住在哪一格无关。打印地址写成 (void *)&x，%p 这个格式只接受通用指针。

同一个 *，两种角色

出现在哪写法它是什么读法
声明里int *p;类型记号：p 的类型是「指向 int 的指针」p 是一个指向 int 的指针
表达式里*p解引用运算符：按 p 里的地址访问那一格顺着 p 去访问那一格

声明里的 * 是类型的一部分，只跟着紧邻它的那一个名字走：

int *p, k;    /* p 是指向 int 的指针；k 是普通的 int 变量 */
int *p, *k;   /* 两个都要指针，就得写两个星号 */
int* p;       /* 与 int *p 同义；星号贴着类型还是贴着名字，只是排版 */

与它配对的是 &：&x 取一个变量的地址，&p 取指针变量自己的地址。

传值还是传地址：两问框架

函数调用里，参数传递可以拆成两个各自独立的问题。两问分开答，「传出去的是副本」与「传出去的是地址」才能同时成立。

  1. 函数拿到的是原件还是副本？ 这由 C 的参数传递规则决定，每一次调用都一样：函数里的形参得到的是调用处实参的副本，调用方那个变量本身不进函数。标准（C17 §6.5.2.2）对这一步的规定是：实参先被求值，每个形参被赋予对应实参的值；函数可以改自己的参数，这些改动影响不到实参。
  2. 这个副本里装的是什么？ 这由实参写成什么样决定：写 x、y（传值调用），副本里装的是值；写 &x、&y（传地址调用），副本里装的是地址。

术语对齐：形参是函数定义里写的参数名（void swap_right(int *pa, int *pb) 里的 pa、pb）；实参是调用处写的表达式（swap_right(&x, &y) 里的 &x、&y）。

问的传值调用 f(x, y)传地址调用 f(&x, &y)
① 拿到的是原件还是副本副本副本
② 副本里装的是什么值：3、8地址：&x、&y
函数能改到调用方的变量吗不能：改的是副本那两格能：顺着副本里的地址解引用，写回原件那一格
一句话传出去的是「装着值的副本」传出去的是「装着地址的副本」

记法：副本不副本，管的是「改的是不是原件那一格」；副本里装什么，管的是「能不能顺着它摸到原件」——装值摸不到，装地址摸得到。

题面问「传出去的那两个值是什么」，要答的是第二问：副本里装的那两个编号，传值调用是 3、8，传地址调用是 &x、&y。题面问「函数拿到的是原件还是副本」，要答的是第一问：副本。两问分开答，合起来是一次完整的说法——传出去的是一个装着地址的副本。

两个 swap 的逐行走查

设 x 在 0x7ffd38、y 在 0x7ffd3c，两个变量在 main 里分别装着 3 与 8。

没起作用的一版：swap_wrong

void swap_wrong(int a, int b) {
    int t = a;     /* t = 3 */
    a = b;         /* a 变成 8 */
    b = t;         /* b 变成 3 */
}

int main(void) {
    int x = 3, y = 8;
    swap_wrong(x, y);
    /* 打印 x = 3, y = 8 */
    printf("x = %d, y = %d\n", x, y);
    return 0;
}

换过来的那一版：swap_right

void swap_right(int *pa, int *pb) {
    int t = *pa;   /* 顺着 pa 摸到 x：t = 3 */
    *pa = *pb;     /* x 那一格写入 8 */
    *pb = t;       /* y 那一格写入 3 */
}

int main(void) {
    int x = 3, y = 8;
    swap_right(&x, &y);
    /* 打印 x = 8, y = 3 */
    printf("x = %d, y = %d\n", x, y);
    return 0;
}
走到哪一步swap_wrong(x, y)swap_right(&x, &y)
调用处：实参求值得到 3 与 8得到 0x7ffd38 与 0x7ffd3c
进函数：新划两格（副本）a 装 3，b 装 8pa 装 0x7ffd38，pb 装 0x7ffd3c
第一行赋值读 a：t = 3*pa 落到 main 的 x：t = 3
第二行赋值改 a：a = 8*pa = *pb：main 的 x 变成 8
第三行赋值改 b：b = 3*pb = t：main 的 y 变成 3
回到 mainx = 3, y = 8（原样）x = 8, y = 3（换过来了）

两版的差别只在第二问：a、b 里装的是值，改动走不出自己那两格；pa、pb 里装的是编号，顺着编号解引用落到的是 main 的格子。pa、pb 自己从头到尾没有被改过。

三条常见误判

误判一：「星号跟整行」

错在哪：把声明里的 * 当成「整行都声明成指针」的标记，于是读 int *p, k; 时以为 k 也是指针。

正确说法：声明里的 * 贴在名字上，只作用于紧邻它的那一个名字。int *p, k; 里 p 是指向 int 的指针、k 是普通的 int；两个都要指针就写 int *p, *k;。星号贴着类型写还是贴着名字写（int* p 与 int *p）只是排版，两种写法效果相同。

误判二：「传指针就是传址」

错在哪：把「传地址」当成 C 的第二套参数传递规则，以为函数收到指针时拿到的是调用方的原件，或者以为「传值调用 / 传址调用」是两套可以挑的规则。

正确说法：C 只有一套参数传递规则，都是传值。收指针的函数拿到的仍然是一个副本，只是这个副本里装的是地址。「传地址调用」这个名字说的是副本里装的东西是地址；传递规则还是传值这一套。

推论：函数里写 pa = &y; 改的是副本这一格的内容，main 里的变量不受影响。要让函数改动调用方的指针变量本身，传进去的得是它自己的地址——那是后续课程的内容。

误判三：「副本改不了原件」

错在哪：把第一问的答案当成整件事的结论——既然参数是副本，函数就一定改不到调用方的变量。这样 swap_right 能换过来就无从解释。

正确说法：能不能改到原件由第二问决定。副本里装的是值，改动止步于副本那两格；副本里装的是地址，顺着地址解引用落到的那一格就是原件。swap_right 里三行赋值改的全是 main 的 x、y，而 pa、pb 自己没有被改过。

自查一句：看到 *pa = ...，先问 pa 里装的是谁的编号，写下去的就是那一格。

读一段指针代码的顺序

  1. 认格子：每个变量住在哪一格，地址是什么（&x、&p 都打印得出来）。
  2. 认星号：落在声明里看类型（int *p 说明 p 的类型），落在表达式里看落到哪一格（*p 是那一格的内容）。
  3. 看到 *p 或 p->name，先确认 p 指着东西：有没有被赋过地址、是不是 NULL。
  4. 看到函数调用，按两问问一遍：拿到的是副本（永远是）；副本里装的是值还是地址。
